# Base de données — Refonte site SIO

Script de création du schéma PostgreSQL (8 tables, clés étrangères, contraintes et index).

**Prérequis :** PostgreSQL 12 ou supérieur.

---

## 1. Créer la base

En ligne de commande (l'utilisateur `postgres` est l'admin par défaut) :

```bash
createdb -U postgres site_sio
```

Ou depuis `psql` :

```sql
CREATE DATABASE site_sio
    ENCODING 'UTF8'
    LC_COLLATE 'fr_FR.UTF-8'
    LC_CTYPE 'fr_FR.UTF-8'
    TEMPLATE template0;
```

## 2. Importer le schéma

```bash
psql -U postgres -d site_sio -f schema_sio.sql
```

Sur Windows, si `psql` n'est pas dans le PATH :

```powershell
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -d site_sio -f schema_sio.sql
```

Alternative depuis une session `psql` déjà ouverte :

```sql
\c site_sio
\i schema_sio.sql
```

Avec **pgAdmin** : clic droit sur la base → *Query Tool* → icône dossier → ouvrir `schema_sio.sql` → *Execute* (F5).

## 3. Vérifier

```bash
psql -U postgres -d site_sio -c "\dt"
psql -U postgres -d site_sio -c "SELECT * FROM role;"
```

Vous devez voir les 8 tables et les 3 rôles insérés (`admin`, `professeur`, `etudiant`).

## 4. Créer un utilisateur applicatif (recommandé)

Ne faites pas tourner le site avec le compte `postgres` :

```sql
CREATE USER sio_app WITH PASSWORD 'motdepasse_a_changer';
GRANT CONNECT ON DATABASE site_sio TO sio_app;
GRANT USAGE ON SCHEMA public TO sio_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO sio_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO sio_app;
```

## Notes sur le script

- Le script commence par des `DROP TABLE IF EXISTS ... CASCADE`. **Il efface les données existantes.** Commentez ce bloc si vous relancez le script sur une base en production.
- Tout est dans une transaction (`BEGIN` / `COMMIT`) : en cas d'erreur, rien n'est appliqué.
- Les identifiants utilisent `GENERATED BY DEFAULT AS IDENTITY` (équivalent moderne de `SERIAL`). L'auto-incrément fonctionne en omettant la colonne `id` dans vos `INSERT`.

### Écarts volontaires par rapport au DBML

| Élément | DBML | SQL | Raison |
|---|---|---|---|
| `fichiers.taille_octets` | `integer` | `bigint` | `integer` plafonne à ~2 Go |
| `logs.ip_address` | `varchar` | `inet` | Type natif, valide IPv4/IPv6 |
| Dates | `timestamp` | `timestamptz` | Gère les fuseaux et le changement d'heure |
| `statut`, `visibilite` | note | `CHECK` | Les valeurs autorisées sont contrôlées en base |

### Comportement des suppressions

| Relation | Suppression du parent |
|---|---|
| `users` → `role` | `RESTRICT` — impossible de supprimer un rôle encore utilisé |
| `fichiers` → `users` | `CASCADE` — les fichiers de l'utilisateur sont supprimés |
| `articles` → `users` | `RESTRICT` — protège les articles publiés |
| `liens`, `galerie_photos`, `logs` → `users` | `SET NULL` — le contenu reste, l'auteur devient `NULL` |

### Automatisme

Un trigger met à jour `updated_at` automatiquement à chaque `UPDATE` sur `articles` et `liens`. Pas besoin de le gérer côté application.

## Insérer un premier administrateur

Le champ `password_hash` doit contenir un hash (bcrypt, argon2), jamais le mot de passe en clair. Générez-le côté application, puis :

```sql
INSERT INTO users (login_users, password_hash, nom, prenom, email, role_id)
VALUES ('admin', '$2y$10$...', 'Dupont', 'Jean', 'admin@sio.local',
        (SELECT role_id FROM role WHERE nom_role = 'admin'));
```
